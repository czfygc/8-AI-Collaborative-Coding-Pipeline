# 浏览器操作实例 — CDP 会话实战沉淀（2026-10-11）

> 来源：一次"注册免费二级域名并托管 Cloudflare"的全自动浏览器会话（Cline 驱动，用户零参与）。
> 工具链：`tmp/cdp-drv.mjs`（35 行零依赖 CDP 驱动）+ Chrome `--remote-debugging-port=9222` + `Invoke-WebRequest` 打 CDP HTTP 端点。
> 结论先行：**能用 API 干的绝不点浏览器；点浏览器必须 IIFE 包一切、提交前逐字核对值、提交后把"表单清空"当成功信号。**

---

## 1. 本次会话操作链（供对照）

Cloudflare B 账号（b093…）add-site 建 zone → 拿分配 NS 对 → DigitalPlat 注册（邮箱验证码从 Gmail 网页取 → GitHub OAuth KYC）→ 注册 dpdns.org 免费域名 → 填外部 NS 指向 CF → CF 侧继续向导加占位 A 记录 → nameserver-directions 页。全程 9222 端口驱动 9 个标签页。

## 2. 坑点清单（全部本次实测）

### 2.1 CDP 驱动层

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| C1 | `window.open()` 被拦 | eval 里开新标签静默失败，list 里什么都没有 | 用 CDP HTTP 端点 `PUT http://127.0.0.1:9222/json/new?<URL编码后的URL>` 建 tab；`PUT /json/close/<targetId>` 关 tab；`GET /json/list` 拿 id。比 Page.createTarget 干净 |
| C2 | tab 子串匹配撞车 | `eval github.com "…"` 命中的是 `github.com/login?client_id=…`（OAuth 跳转页）而不是 `github.com/` 主会话页，拿到的登录态完全是错的 | **匹配串必须保证全浏览器唯一**；OAuth/重定向场景先 `GET /json/list` 用 targetId 精确定位，必要时关掉干扰 tab 再匹配 |
| C3 | eval 变量二次声明 | 同一页面多次 eval `var v=…` → `SyntaxError: Identifier 'v' has already been declared`（页面上下文是持久的！） | **所有 eval 一律 IIFE 包裹** `(()=>{…})()`，这是硬规矩不是风格 |
| C4 | ASCII 编码毁中文 | `Set-Content -Encoding ascii` 写含中文的 JS → 正则里中文变 `???` → `SyntaxError: Nothing to repeat` | 含非 ASCII 的 expr 文件一律 `-Encoding utf8`；纯 ASCII 才能用 ascii |
| C5 | cdp-drv 功能缺口 | 无建 tab / 关 tab / 截图 / 精确 tab 定位；`nav` 只 dump 3500 字符（正文在 tail 时看不见） | 见 §4.3 升级清单；当前用 HTTP 端点补建/关 tab，正文用 eval `document.body.innerText.slice(-N)` 补读 |

### 2.2 SPA / React 页面层

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| S1 | 重渲染吞掉已填值 | select 用原生 setter 设好 `.dpdns.org`，几秒后 SPA 重渲染 `.value` 又回默认值——**点提交时提交的是空表单** | 提交前**在同一个 eval 里先读值再点按钮**，读到的不是预期值就中止；不要"填完等几秒再点" |
| S2 | 提交成功=表单清空 | 点"更新域名服务器"后输入框全空，第一反应是失败重填——其实成功了 | 把"提交后表单重置/清空"当成功信号；验证走权威 DNS 查询，不是 UI 文案 |
| S3 | React 受控组件 | 直接 `.value=` 不触发状态 | `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set` + dispatch `input`+`change`（select 同理用 `HTMLSelectElement.prototype`，textarea 用 `HTMLTextAreaElement.prototype`） |
| S4 | 非 React 表单 | DigitalPlat KYC 页是普通 HTML，原生 setter 反而报 `Illegal invocation`（跨 realm prototype 问题偶发） | 两路都试：先 `el.value=v` 直赋 + change，不行再原生 setter；以"同 eval 内读回值"为准 |
| S5 | 懒加载正文 | CF 页面打开 10s 内 `body.innerText` 只有侧边栏，主区空 | sleep 4-12s 再探测；或对已知结构直接 querySelector 探测（比 innerText 可靠） |
| S6 | 弹层按钮 disabled 有语义 | CF 套餐确认框 Confirm 永久 disabled——因为 Free 已是当前套餐，**没有可确认的变更**；正确动作是 Cancel 关掉，不是硬解 disabled | 碰到 disabled 按钮先回答"它在等什么状态"，多数时候是"无需操作" |

### 2.3 Cloudflare 仪表盘专项

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| CF1 | add-site 直链被弹回 | `/domains/add-site` 直接 nav 回 home（技能已记，本次复证） | 从 `/domains` 页**点击** "Add domain" 按钮进入 |
| CF2 | zone 建好 ≠ 向导走完 | 填完域名 Continue 后 URL 已是 `/<zone>/select-plan`，**zone 实体已存在**（域名列表显示 Pending setup）；向导剩余步骤可跳 | 直接 nav `/<zone>/manual-entry`（DNS 手录页）→ 加完记录点 "Continue to activation" → 落到 `nameserver-directions` 拿 NS 对 |
| CF3 | 加购弹层（APO $5/mo） | 套餐页 Confirm 前有个 "Add APO for $5.00/mo" 复选框 | 点 Confirm 前**先读 `input[name=add_addon_apo].checked`**，必须 false |
| CF4 | 会话中途过期 | dash.cloudflare.com 突然 302 到 `/login`（空 body），再直接 nav 还出 `chrome-error` | 检测到 login 跳转就重走登录；重 nav 前 sleep 3s 让页面加载 |
| CF5 | 加 zone 零绑卡 | B 账号加 zone 全程无绑卡、无验证（复证"勿给 B 绑卡"红线不冲突） | — |

### 2.4 DigitalPlat（dpdns.org/us.kg 系）专项

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| DP1 | 免费插槽要注册后才 KYC | Signup+邮箱验证码后能登录；点"注册域名→注册"才跳 `/user/kyc` 要求 GitHub OAuth | 流程预期：注册账号 ≠ 能注册域名；KYC 是第二道门 |
| DP2 | KYC 回调吃掉会话 | 第一次 OAuth 回调页（"通知"）显示后自关，回 dashboard 变回登录页 | 重新登录再走一遍 KYC 即通过（幂等）；**在已登录会话里再点 KYC** 是关键——第二次从带会话的 tab 发起，GitHub 直接放行，URL 带 `oauth_notice=github_kyc_verified` |
| DP3 | GitHub OAuth 弹出的登录页 | DigitalPlat 发起的 OAuth 跳到 `github.com/login?client_id=…`，虽然另一个 tab 已登录，这个新上下文仍显示登录表单 | **把已登录的 GitHub tab 直接导航到 authorize URL**（从登录页 return_to 里抠出完整参数），会话 cookie 生效，GitHub 自动批准并回调 |
| DP4 | 免费额度规则随时变 | qzz.io 现已**消耗付费插槽**（教程还说免费）；us.kg/xx.kg 暂停/收费；qd.je 不在 PSL | 注册前必读页面上的"插槽记账"区（免费 X 个/付费 Y 个），别信旧教程；PSL 当场 curl 验证 |
| DP5 | 域名字符串漂移 | 流程锚定 `tfes2cnhlbgk`，最终注册落盘的是 `sddsfdgfdh.dpdns.org`（多手操作/页面重渲染期间输入漂移）→ **CF 侧 zone 名与注册域名不一致，两边对不上** | 单一事实源：注册成功页显示什么域名，就以它为准回改 CF；每跳一次页面核对一次域名字符串 |
| DP6 | NS 更新 UI 状态滞后 | 点"更新域名服务器"表单清空（成功），但页面仍显示 DigitalPlat DNS 文案 | 权威验证：`Resolve-DnsName <domain> -Type NS -Server <注册局NS IP>`（dpdns.org 权威 = ns1-4.digitalplat.org），别信 UI 也别信本地缓存 |

### 2.5 环境层

| # | 坑 | 现象 | 解法 |

## 3. 更好的操作方法（下次照这个来）

### 3.1 API 优先原则（最重要）

- **Cloudflare 有全套 API**，且 B 账号的 Account API Token 已存 `titan_secrets.env`（CF_B_TOKEN，11 权限）。加 zone、加 DNS 记录、查 NS、改 nameserver 全部有 REST 端点：
  - `POST /zones`（建 zone）→ 响应直接给 assigned NS，不用点四层向导
  - `POST /zones/{id}/dns_records`（占位 A 记录）
  - `GET /zones/{id}/nameservers`
  - 环境变量 `CLOUDFLARE_API_TOKEN` + `npx wrangler whoami` 已验证可用（技能 §4）
- **DigitalPlat 同理有 API 谱系**（nic.us.kg 遗产），DOM 点击前先看 Network 面板里的 XHR，直接 curl 复刻。
- 判定口诀：**浏览器只用来"发现 API"和"处理无 API 的交互"（OAuth 授权页、验证码图形），一旦拿到端点+token，后续一律 curl/脚本。**

### 3.2 Playwright 替代裸 CDP eval

`playwright-core@1.64` 已在 package.json（技能有记录但本次没用上，全程裸 eval——这是退步）。Playwright 带来的实质增益：

- `context.newPage()` 不受弹窗拦截；`page.waitForSelector/loadState` 消灭 `Start-Sleep` 猜时序
- 定位器自动重试 + 可见性过滤，消灭 `offsetParent!==null` 手写过滤
- `page.on('dialog')` 处理 confirm/alert；`page.screenshot()` 留证据
- 多 page 管理自带 targetId 语义，消灭 C2 撞车
- 接入方式不变：`chromium.connectOverCDP('http://127.0.0.1:9222')`，登录态/profile 全复用

**分工建议**：探索/侦查用 cdp-drv（快、零依赖）；确认流程后的**重复执行、多步向导**切 playwright 脚本。

### 3.3 CDP HTTP 端点速查（本次实战验证）

```
GET    /json/list                      # 全 tab（含 targetId）
PUT    /json/new?<urlencoded-url>      # 建 tab（绕过弹窗拦截）
PUT    /json/close/<targetId>          # 关 tab
PUT    /json/activate/<targetId>       # 前台切换
```

### 3.4 网络层反推（UI 不可靠时的终极手段）

DOM 状态骗人（S1/S2/DP6）时，两条硬验证路径：
1. **权威 DNS 直查**：`Resolve-DnsName <domain> -NS -Server <父区权威IP>`，绕过本地缓存和 UI 谎言
2. **CDP Network 域抓 XHR**：`Network.enable` + `Network.requestWillBeSent` 把 SPA 的真实 API 调用和 payload 抠出来，之后 curl 复刻——本次没做，下次 NS 更新类操作首选

## 4. 缺失但值得装的工具 / 插件 / 技能

| 优先级 | 工具 | 干什么用 | 状态 |
|---|---|---|---|
| ★★★ | **Playwright MCP**（`@playwright/mcp`） | agent 原生浏览器工具：语义化 click/fill/snapshot，官方维护，接进 MCP 配置后四个客户端都能用，替代手写 eval 脚本 | 未装，建议装（工作区内 `npm i @playwright/mcp`，M7 四条底线内） |

## 6. 一句话原则

1. **API first**：浏览器是发现工具，不是执行工具。
2. **IIFE 包一切**：页面上下文持久，裸 eval 迟早撞变量名。
3. **提交前读值，提交后信清空**：DOM 会骗人，值读回+权威查询不会。
4. **tab 定位用 targetId**：子串匹配在 OAuth/重定向场景必翻车。
5. **密钥走 base64 字节通道**：M9 在浏览器场景同样成立。
